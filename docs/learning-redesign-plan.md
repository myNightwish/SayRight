# 学习流程改造（2026-10-28 修订）

本文件以用户最新确认的三个模块为准，取代此前「只呈现一个情境、隐藏参考句」及「超额标记先批量待选」的方案。

## 一、表达库与本轮正在练

表达库负责收集，标记想练的数量不限。首次进入正在练，从最近标记中接纳最多 10 张，其余保留为候补。已有本轮之后，不因新的标记、刷新或同步挤走成员。

本轮直接展示英文句子、使用情境以及造句入口。移出将表达放回暂存；删除仍需确认，并同步删除记录。两者都会留下空位，不自动递补。候补每条有「确认补入」，只有用户点击才入队；满 10 张时不能补入。结束本轮需确认，仅归档确认的本轮成员，候补不受影响。下一轮由用户明确开启，取最近标记的最多 10 张。

## 二、逐句造句与自评

每张卡可以照着目标句式，换自己的经历造句，调用现有本地模型判断语法、搭配及目标用法。正确的其他说法仍可被认定为表达成立；是否练到了目标用法单独解释，不要求复刻整句。

反馈保存提交的句子、参考表达、时间与 AI 建议；不会自动调整自评分、归档或修改原收藏。审核确认表达成立且用上目标用法后，可主动选择「用我的句子替换」。只采用那次已经审核的原始造句，不采用未审核的输入或 AI 建议句；保留稳定卡片标识、原参考句、来源与每次替换记录。替换后自评分需重新确认，后续对话使用新的主句。自评分为 1～5：1 还很陌生，2 看例句能模仿，3 需要提示，4 可以独立造句，5 换场景也能用。可以随时重评，AI 不替用户打分。参考句修改后，旧评分不再用于解锁。

## 三、本轮已学材料的情境对话

至少有一张本轮卡片，且每张自评都达到 4 分，才可开启情境对话。候补不计入门槛；补入尚未自评的卡片会重新锁定。这个门槛表示用户准备好了，不是系统认证掌握。

合并可见的日常对练与情境对练入口。旧对话 URL 进入同一个门槛，无法绕过；每次开始（包括重新开始）读取最新主句，并以当前本轮材料生成对话，不从整个表达库或候补中抽取。采用自造句后，模型只收到当前句子，不附带旧情境与旧构式。已开启对话中如材料变化，暂停并提示重新开始；旧的异步响应不会覆盖新对话。AI 从其中选择适合一场交流的表达；返回不属于本轮的目标时停止启动并提示重试。

## 数据与发布

沿用 corrections 与 drillState 的既有云同步，不增加第二套存储环境。首次本机变更前在 IndexedDB 的 nuance-learning-backup / snapshots / queue-v1 保存原始快照，备份失败则不写入。

本轮事件使用 @nuance/window/（version 3），成员历史使用 @nuance/queue/，自评分使用 @nuance/rating/，造句记录使用 @nuance/practice/，替换历史使用 @nuance/adoption/。主句用 expressionChangedAt 独立合并，避免旧设备的笔记或星标把新的主句覆盖回去。保留旧调度和轮次历史。queueChangedAt 独立合并学习状态，避免较新的星标或笔记撤销归档。AI 请求绑定原卡片、参考句及轮次，材料变化后不把反馈写入替换卡片。

网页使用当前服务的模型接口；插件继续使用本机 48773 的模型能力，两者同步仍指向同一线上环境。运行 npm test 后更新后台安装副本；插件需重新加载，线上需部署新代码。没有执行清库或生产数据测试写入。
